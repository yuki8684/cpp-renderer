## 2. ★★ 三条主线（阶段一的骨架）

### 主线 A · `(α, β)` 重心坐标，一个概念用了 6 次

```
P = a + α(b−a) + β(c−a) = (1−α−β)·a + α·b + β·c
```

| 天 | 用途 | 关键细节 |
|:--:|---|---|
| 13 | 判断点在不在图形里 | `0≤α≤1, 0≤β≤1`（四边形）/ `α≥0, β≥0, α+β≤1`（三角形）|
| 15 | 插值法线 | 最后**必须** `unit_vector` |
| 22 | 插值 UV | **不能**归一化 —— UV 是坐标不是方向 |
| 22 | 兜底 UV | `rec.u = α; rec.v = β` —— 能用，但永远不对 |
| 25 | 插值切线 | 和法线一样要投影到切平面 |
| 27 | 顶点切线共享 | 把"每三角形解一次"换成"每顶点解一次" |

**一句话：位置、法线、UV、切线都挂在"角"上，用同一组权重。**

### 主线 B · pdf 的演进：从"藏在代码里"到"摆在明面上"

这是阶段一最后、也是最难的一条线。

| 天 | 发生了什么 | 结论 |
|:--:|---|---|
| 3 | `rec.normal + random_unit_vector()` | 当时不知道为什么这么写，只是书上这样 |
| 17 | NEE：`1/pdfw == 光源立体角 Ω` | 第一次知道 pdf 可以**被测试** |
| 19 | 证明上面的写法**就是**余弦加权（`θ = α/2`）| `attenuation = albedo` 被"证明"了 |
| 19 | 加均匀半球对照分支 | 必须写 `2·cosθ·albedo` —— **第一次发现 attenuation 依赖采样方式** |
| 29 | 把 `pdf` 单独暴露成 `scattering_pdf()` | `attenuation` 降格为纯 BRDF，`cosθ/pdf` 交给积分器 |
| 29 | **三场景逐字节相同** | 证明显式化是恒等变换，不是改了算法 |

**这条线的终点是 MIS 的前置条件**：要在两种采样策略之间加权，pdf 必须是可查询的。

---

### 主线 C · "数学恒等变换" 的验收方法：字节级不变

**这是整个阶段一最值钱的方法论**，比任何单个公式都重要。

| 天 | 改了什么 | 验收标准 |
|:--:|---|---|
| 9 | 线性列表 → BVH | PPM **172,127 B 字节相同** |
| 10 | 递归 BVH → 扁平数组 + 干掉 `std::fmax` | 同上，且 5.55 s → 1.82 s |
| 13 | 加 `pad_to_minimums()` | 有/无 BVH 字节相同 |
| 14 | `Quad` → `Triangle` 两种拆法 | 字节相同 |
| 29 | `attenuation` 拆成 BRDF + 积分器补 `cosθ/pdf` | 三场景 MD5 全部相同 |

**为什么要求字节级：** 只有"完全不改结果"才允许你说"这是重构，不是改需求"。
一旦差了几个像素，你就得先解释清楚差在哪 —— 而那通常意味着随机数序列错位，
不是数学错了。

## 4. ★ 简历 / 面试素材（每条都带数字）

面试官不看代码，只看数字和你**能不能解释这些数字**。

| 素材 | 说法 | 能被追问的点 |
|---|---|---|
| BVH 加速 | N=8095 时 **93.4×**（朴素斜率 0.98 → BVH 斜率 0.17）| 为什么不是线性？斜率 0.17 的理论值是多少？ |
| 扁平化只值 6% | 递归→数组 **5.55 s → 5.2 s** | 那真正的瓶颈是什么？（`std::fmax` 被编译成函数调用）|
| 多线程 | 24 逻辑核 **4.32×**，进程吃满 22.68 核 | 为什么不是 24×？（功耗墙 / P+E 异构 / 超线程 / 带宽）|
| NEE | 64 spp 噪声 **38.38 → 8.05**，等效 16× 加速 | 为什么 NEE 不改变结果只改变方差？ |
| 余弦加权 | 权重标准差 **0 vs 0.577**，`E[cos] = 0.66639`（理论 2/3）| 为什么余弦采样是"零方差"的？ |
| 顶点法线插值 | 误差 **10.55° → 1.2e-06°** | 为什么球面插值是精确的，圆环不是？ |
| 共享切线帧 | **3.756° → 0.215°（17.4×）** | 但为什么画面上看不出来？（400×225 下每三角形 2–3 像素）|
| P6 二进制 | 体积 **3.493×** 更小；端到端渲染字节相同 | P3 和 P6 的头部差在哪？为什么 2 字节要大端？ |
| 显式 PDF | U7/U8 相等证明 attenuation 与采样解耦 | δ 分布为什么没有 pdf？ |
| 工程规模 | **197 条断言**、11 个测试文件、0 warning | 变异测试做过吗？结果如何？（13 条只红 1 条）|

**最能加分的两条（因为反直觉、且有实测数据）：**
1. **"扁平化只值 6%，真凶是 `std::fmax` 的 NaN 语义"** —— 讲"我以为 A，实测是 B"
2. **"共享切线帧误差降 17 倍，但画面上看不出来"** —— 讲"正确性改进不等于观感改进"
