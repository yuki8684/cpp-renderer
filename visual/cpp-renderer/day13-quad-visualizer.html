01为什么第二块几何体是平行四边形

球能证明渲染器活着，但盖不出一个房间。

左墙、后墙、天花板、地板 —— 这些都不是球。Day 10 之后 BVH 已经能吞下成千上万个物体，Day 12 把玻璃、Fresnel、gamma 也修好了， 可 Cornell Box 迟迟没开工：缺的不是光照模型，而是一块平的、有边界的、能当墙用的面。

三个候选方案，各有各的代价：

  • 无限平面：一个法线一个常数就够，但没有边界。光会跑到"世界外面"，也做不成面光源。
  • 三角形：最通用，任何网格都能拼出来。但参数化要重心坐标，内部判定多一步，而且单看一个三角形不容易心算。
  • 平行四边形：一个角加两条边向量。边平行、共面是构造出来就成立的，不需要验证；判定只要两次比较。

真正的理由是最后一条：平行四边形是"用两个方向张成"的最简单形状，而三角形只是把它沿对角线切一半。 今天写好的整套机制（平面求交、平面内坐标、内部判定、包围盒），明天换成三角形只需要改 is_interior 的一个函数体 —— 所以代码里它是 virtual。

一个点 + 两个位移

Quad(const Point3& Q, const Vec3& u, const Vec3& v, ...)
四个角是 Q、Q+u、Q+v、Q+u+v。 注意类型：Q 是点，u / v 是位移。C++ 里它们都是 vec3， 但语义必须分清 —— 推导里写的是"点 + 位移"，不是"点 + 点"。

参数化 · 把面变成二元函数

02参数化：一块面就是一个二元函数

形状内的每一点，都能被一对数字 (α, β) 唯一编号。

把平行四边形写成

平行四边形参数方程 P(α, β) = Q + αu + βv     α, β ∈ ℝ

α、β 取遍全体实数时，它给出的是整张无限平面；再加上两条不等式 0 ≤ α ≤ 1、0 ≤ β ≤ 1，才被裁成平行四边形。 这个分界正是求交代码的结构：先解平面（无约束），再判 α、β（约束）。

四个角对应四组边界值，记住它们，后面所有公式都能自己验算：

(α, β)位置几何意义
(0, 0)Q起始角
(1, 0)Q + u沿 u 走到头
(0, 1)Q + v沿 v 走到头
(1, 1)Q + u + v对角
(0.5, 0.5)Q + 0.5u + 0.5v中心

为什么不用四个角点？四个点 = 12 个数，而且未必共面、未必对边平行—— 你还得额外验证。 三个向量 = 9 个数，共面和平行是免费的：四条边自动是 u, v, −u, −v。

读动画
拖动 α、β 滑块（或让它自动扫描），看 P 怎么在四个角之间滑动。 两条虚线是分解路径：先从 Q 沿 u 走 α 倍到达 Q+αu，再沿 v 走 β 倍到达 P。 注意 u、v 不垂直时，"沿 u 走了多远"和"离某条边有多远"是两件不同的事 —— 这正是不能用直觉代替公式的原因。

由此产生一个必须回答的问题：给定平面上一点 P，怎么反求 α、β？ 这是 §5 的全部内容，也是今天数学上最有意思的一步。

法线 · 一次叉积，两个答案

03法线：方向和面积同时到手

叉积给出的不只是一个垂直方向，它的长度还等于这块面的面积。

叉积 = 法向 + 面积 n = u × v,    |n| = |u||v| sin θ = 平行四边形面积

方向由右手定则决定：n ⊥ u 且 n ⊥ v，也就是垂直于整张平面。 长度是 u、v 张成的平行四边形面积 —— 这不是巧合，它是 §5 里"α 等于面积比"的全部依据。

为什么四个角自动满足同一条平面方程？因为 n·u = (u×v)·u = det(u, v, u) = 0（行列式有两列相同），同理 n·v = 0。于是

平面方程（隐式） n̂ · P = D,    D = n̂ · Q ⇒ n̂·(Q+αu+βv) = n̂·Q + α·0 + β·0 = D，α、β 取什么都成立

D 的意义：它把一个"面"压成了一个标量。想知道某点在平面哪一侧，只算 n̂·P − D 的符号就行（Day 14 做面光源采样时会反复用到）。而判断"在不在平面上"就是看它是否等于 0。

include/quad.h · 构造函数

这四行只跑一次，却服务几百万条光线。算一下量级：400×225 的图、每像素 32 个采样 ≈ 288 万条主光线， 每条都至少调一次 hit()；而场景里只有 5 个 Quad。把不随光线变化的量全部前置， 是光线追踪器的第一条性能原则 —— 后面 BVH 把盒子也缓存起来，是同一个思路的放大版。

量纲检查（三秒抓出一个 bug）
n̂ 无量纲 ⇒ D 有长度量纲；w = n/(n·n) 有 1/长度 量纲， 因为它要乘上 p×v（长度²）才能得到无量纲的 α。注意 n/(n·n) = n̂/|n| —— 说明即使用单位法线，也还得再除一次 |n|， 绝不能只写 n̂，否则 α 会整体放大 |n| 倍，所有点都被判到形状外面。

还有一个退化情形：u ∥ v 时 n = 0，w 会除零， 平面方程也失去意义（形状退化成线段）。今天的场景里不存在，但这是构造函数里应该加 assert 的地方 —— 让错误在构造时就炸，而不是在渲染到第 200 行时输出一片 NaN。

求交 · 一个除法

04射线 × 无限平面：一个除法解决

把射线代进平面方程，未知量只有一个 t。

射线写成 P(t) = O + t d，平面写成 n̂·P = D，直接代入：

推导 n̂ · (O + td) = D n̂·O + t (n̂·d) = D t = D − n̂·On̂·d

分母只出现在一处：n̂·d。它有两个身份： 是否为 0 决定方程有没有解；符号决定光线是从正面还是背面穿过平面。 因为 n̂·d = |d| cos θ，所以

  • n̂·d = 0 ⟺ θ = 90° ⟺ 光线平行于平面（或整条躺在平面里，此时有无穷多解，但我们判"没打中"）。
  • n̂·d < 0 ⟺ 光线逆着法线走 ⟺ 从正面射入。这与 set_face_normal 的判据是同一个。
include/quad.h · hit() 第一步

三个失败模式，务必分清楚，因为它们的修复方式完全不同：

失败模式判据物理含义怎么修
平行|n̂·d| < 1e-8永远不相交，或整条在面内直接 return false
在身后t < t_min平面在光线反方向不用修，窗口判据已覆盖
超出窗口t ≥ t_max被更近的物体挡住了不用修，BVH 靠它剪枝
在平面内、不在形状内α,β ∉ [0,1]打到了"无限平面"的其余部分交给 §5、§6

两个细节值得停下来想。第一，为什么用 fabs：光线可以从两边平行于平面， denom = +0.0 和 −0.0 都应该被挡掉，只判 denom == 0 是靠不住的。 第二，1e-8 是工程折中，不是数学：理论上只有精确的 0 才平行，浮点下"几乎平行"的光线会算出巨大的 t， 然后自然被 t_max 或 α、β 判掉；提前挡掉只是省一次除法、避免 inf 流进后续运算。 另外，camera.get_ray 的方向没有归一化，所以 denom 的量纲其实是 |d| —— 这个阈值并不是尺度无关的， 换个相机模型就要重新想。

为什么先解平面、再判形状
这是"先解约束、再筛范围"的通用套路：平面求交是一个除法，非常便宜；形状判定是两次叉积 + 四次比较， 但完全不含除法。把便宜且必做的放前面，贵且常常不需要做的放后面 —— 与 BVH 先测盒子再测三角形是同一个哲学。
核心 · 两次叉积

05平面内坐标：叉积把 3×2 系统变成 1×1

已知 P 在平面上，求 α、β 使 p = P−Q = αu + βv。

这是一个 3 个方程、2 个未知数的系统。它超定，按理说无解 —— 但 P 一定在平面上， 所以第三个方程是前两个的线性组合，是冗余的。麻烦在于：直接丢掉某个坐标，会在 u、v 某个分量为 0 时除零。 叉积能绕开这个陷阱。

关键一步：把未知量"叉掉"一个。两边同时右乘 v：

消去 β p × v = α(u × v) + β(v × v) = αn 因为 v×v = 0，β 直接消失了

现在两边只剩一个方向 n，点乘 n 把它变成标量：

n·(p×v) = α (n·n)  ⇒  α = n·(p×v)n·n

同理，两边右乘 u：p×u = α(u×u) + β(v×u) = −βn（注意 v×u = −n）， 于是 β = n·(u×p)/(n·n)。把除法提前打包成

代码里的 w w = nn·n   ⇒   α = w·(p×v),   β = w·(u×p)

注意两个叉积的自变量顺序不一样：α 用 cross(p, v)，β 用 cross(u, p)。 这不是笔误。它们其实是同一条规则 —— "p 与另一条边叉乘" —— 只是 v×u = −n 多出来的负号需要靠交换顺序补回来。 如果写成 cross(p, u) 求 β，你会得到 −β，然后所有点都被判到形状外：画面全黑，而代码看起来"没错"。

α 就是一个面积比

把 p×v = αn 两边取长度：|p×v| = |α| |n|。 也就是说，α 等于"p 与 v 张成的平行四边形面积"除以"u 与 v 张成的面积"。 β 同理。整个过程没有三角函数、没有开方，只有叉积和点乘 —— 这是它比"算角度"优雅的地方。 动画里切换到 α / β 视图，可以看到那两块被涂色的面积，以及它们的比值。

手算（单测组 B）Q=(0,0,0), u=(2,0,0), v=(1,0,2), P=(2,0,1)
n = u × v(0·2−0·0, 0·1−2·2, 2·0−0·1) = (0, −4, 0)
w = n/(n·n)(0,−4,0)/16 = (0, −0.25, 0)
p = P − Q(2, 0, 1)
p × v(0·2−1·0, 1·1−2·2, 2·0−0·1) = (0, −3, 0) → α = 0.75
u × p(0·1−0·0, 0·2−2·1, 2·0−0·2) = (0, −2, 0) → β = 0.5
验算Q + 0.75u + 0.5v = (1.5,0,0) + (0.5,0,1) = (2,0,1) ✓
include/quad.h · hit() 第二步

为什么不用 Cramer 法则？

把 (u, v) 当成 2×2 基，硬解正规方程（Gram 矩阵）也能得到完全等价的公式：

α = (p·u)(v·v) − (p·v)(u·v)(u·u)(v·v) − (u·v)²

数学上一样对，工程上差很多：它每次求交都要做 2 次除法、算 5 个点积； 而叉积版把所有除法搬进构造函数（w 里），hit() 只剩 2 次叉积 + 2 次点乘，0 次除法。 分母 (u·u)(v·v) − (u·v)² 正是 |n|²，所以两种写法在 u∥v 时同时退化 —— "法线不为零"和"α、β 唯一"是同一件事。

判定 · 四行代码

06内部判定：整个 Quad 只有这里认识"形状"

求交和坐标都是仿射的，与形状无关；只有这四行编码了"平行四边形"。

is_interior 0 ≤ α ≤ 1   且   0 ≤ β ≤ 1

边界取闭区间（>=、<=）。单测明确要求角点 (0,0) 和对角 (1,1) 算命中。 闭区间的代价是：两块相邻的平行四边形共边时，公共边会被两个物体各命中一次 —— 三角形拼网格时要小心重复着色。 今天只有 5 面互不相接的墙，闭区间更符合直觉。

include/quad.h · is_interior

为什么它是 virtual？因为明天的三角形只需要覆盖这一行：

形状判定式说明
平行四边形a ∈ [0,1] && b ∈ [0,1]今天
三角形a > 0 && b > 0 && a + b < 1明天，继承 Quad，只改这里
内切圆盘(a−.5)² + (b−.5)² < .25换个判定式而已

动画左半是 (α, β) 平面，右半是同一对数字对应的三维点。被涂色的区域就是"会被渲染出来"的区域 —— 形状的差别只体现在这个集合上，求交、法线、包围盒一行都不用动。

概念澄清
这里的 (α, β) 是仿射坐标（平行四边形坐标），不是三角形的重心坐标。 重心坐标 (λ₁, λ₂, λ₃) 满足 λ₁+λ₂+λ₃ = 1，把 λ₃ = 1−α−β 消掉之后，才得到这里的二维版本。 所以三角形判定里的 α + β < 1 不是"漏了一项"，而是第三个坐标必须为正。
陷阱 · 今天最重要的一节

07零厚度：一个只有平面才会踩的坑

同一份代码，不加 BVH 完全正常，加上 BVH 之后五面墙全部消失。

回到 Day 8 的 slab 测试：三个轴各给一段区间 [t₀, t₁]，取交集， 判据是 t_min >= t_max 就返回 false（"擦过、退化成一点"算没打中）。 球从来不会出问题：三个方向都有厚度，每个轴的区间都是一段有长度的区间。

平行四边形会。当它躺在一个坐标平面上时，包围盒在该轴的厚度是 0。用动画里那条射线算一遍：

数字推演

平面 y=0，O=(1, 3.2, 0.2)，d=(0, −1, 0)， 盒子 x∈[−2,2], y∈[0,0], z∈[−1.5,1.5]

x 轴：inv_d = +∞ → t₀ = −∞, t₁ = +∞  （无约束） y 轴：t₀ = t₁ = (0 − 3.2)/(−1) = 3.2  （退化成一点） z 轴：inv_d = +∞ → t₀ = −∞, t₁ = +∞ 交集：t_min = max(0.01, 3.2) = 3.2，t_max = min(∞, 3.2) = 3.2 → 3.2 ≥ 3.2 → return false

而 Quad::hit 明明在 t = 3.2 命中。矛盾只来自一句话： "退化成一点算不算命中"—— 几何上算，slab 判据定义成不算。

最阴险的地方
不加 BVH 的时候，这个 bug 完全不出现：盒子根本不参与求交，五面墙照常渲染。 一旦打开 BVH，平面几何体整个消失。所以验收必须两步： --no-bvh 和默认输出必须逐像素一致。如果只测一种，你得到的是一个"看起来对"的渲染器。

修法不是改判据，而是改盒子：给它撑开一点点。

include/aabb.h · pad_to_minimums()

方向必须是"变大"。盒子只是保守近似：变大 → 少排除几根光线（性能影响可以忽略）→ 仍然包含全部几何体 → 不会漏命中。 反过来缩小，就可能漏掉真实交点 —— 这类 bug 表现为画面边缘随机缺几条像素，极难复现。 这是包围盒的一条铁律：宁可放过，不可错杀。

delta = 1e-4 的选取也有讲究。场景尺度是几个单位，1e-4 远大于双精度在这个尺度上的舍入误差（约 1e-16）， 又远小于任何看得见的几何特征。太大（比如 0.5）会让 BVH 的盒子互相重叠、剪枝变差；太小则撑不出可用区间。 量纲上它和被撑开的轴同单位，所以换场景尺度时应该跟着缩放 —— 今天不需要，但值得记一笔。

包围盒本身怎么算

include/quad.h · set_bounding_box()

两个对角盒子取并。为什么两条对角线就够？AABB 对每个轴独立取 min/max， 所以 AABB(Q, Q+u+v) 覆盖两个对角，AABB(Q+u, Q+v) 覆盖另外两个； 而平行四边形上任何一点都是四角的凸组合，凸组合的包围盒等于顶点的包围盒 —— 四个角全覆盖，整块面就全覆盖。

画面里为什么有缝隙
五块板并不是严丝合缝的盒子：左右墙在 x = ±3，但只从 z = 1 铺到 z = 5； 后墙在 z = 0；地板和天花板只铺 x ∈ [−2, 2]。于是墙角、地板两侧都露出了天空。 这不是渲染错误 —— 它与仓库里的 gallery/day13-quads.png 逐块一致。 作为"验证图元"的测试场景，五块互不相接的板反而更好用：一眼就能看出每块板的边界有没有落在该在的位置。

下面的渲染器是 C++ 代码的逐行移植：同样的 n̂、D、w， 同样的两阶段求交，同样的 sqrt gamma，max_depth 取 4 以控制浏览器开销。 分辨率 288×162，逐帧累积采样，噪声会随时间收敛。

三个可以亲手验证的结论
① 面数 1→5：房间一面一面搭起来，注意每加一面，画面就少一块天空。
② 关掉内部判定：画面会整幅变黑。五张无限平面把天空完全封在外面，射线在平面之间来回弹射， 4 次弹射预算用尽也见不到光 —— 这是 is_interior 的另一半职责：它不只决定"墙有多大"， 还决定"世界是不是封闭的"。
③ 与 gallery/day13-quads.png 对照：构图、配色应一致；差异只来自采样数与浏览器浮点细节。

最后提醒：这个 JS 渲染器不是要替代 C++，它只是把同一组公式搬到浏览器里，让参数可以实时改。 真正的验收仍然是那两条：单测 25 条全过，以及 --no-bvh 与默认输出逐像素一致。

先自己写答案，再展开对照。答不上来的，回对应小节。

如果 u=(1,0,0)、v=(2,0,0)，会发生什么？

两条边共线，形状退化成一条线段，n = u×v = 0，w = n/(n·n) 变成 0/0 = NaN。 平面方程 n̂·P = D 也失去意义（没有唯一法线）。修复方式是在构造函数里判断 dot(n,n) 是否接近 0 并报错，而不是让 NaN 流进渲染循环。

如果把 D 写成 dot(n, Q)（未归一化），但分母仍用 normal，t 会错多少倍？

错 |n| 倍。平面方程 n·P = n·Q 与 n̂·P = n̂·Q 描述同一张平面， 但分子分母必须用同一个尺度的法线。混用会得到 t' = |n|·t： 平面位置完全错掉，而画面可能"看起来还有个盒子"。这类错误单测一抓就现形（A 组 t=5）。

为什么 α 用 cross(p,v)，β 却用 cross(u,p)？都写成 cross(p,·) 会怎样？

因为 p×u = −βn，比 p×v = αn 多一个负号。两条规则其实一致（p 与另一条边叉乘）， 只是 β 需要交换一次顺序来补符号。若都写 cross(p,·)，会得到 −β，于是 β∈[0,1] 的点全被判成外部， 渲染结果是空的 —— 代码"没有语法错误"，只有数学错误。

把 is_interior 改成 a>0 && b>0 && a+b<1，画出来是什么？边界上的点会怎样？

左下角那个三角形（Q、Q+u、Q+v 围成）。斜边 α+β=1 上的点会被判为外部， 因为用的是严格大于/小于。两个这样的三角形拼成正方形时，对角线不会被重复命中 —— 这正好是三角形网格想要的行为。 但今天如果直接这么改，四边形会被切成半个，且两条直角边上的点全丢。

把 delta 改成 0.5 会怎样？改成 0 呢？

delta=0：等于没修，平面在 BVH 下消失（§7 的数字推演）。 delta=0.5：不会出错，但每个平面的盒子被撑成 0.5 厚的板，BVH 节点互相重叠， 剪枝效率下降 —— 5 个 Quad 看不出来，上千个三角形时会明显变慢。 正确量级是"远大于浮点误差、远小于几何特征"，1e-4 对当前场景合适。
