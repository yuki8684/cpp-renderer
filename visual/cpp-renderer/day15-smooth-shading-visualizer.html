01硬棱不是几何问题，是法线问题

先看仓库里 Day 15 的真实输出。同一批三角形，只把法线的算法换掉：

左边那张图里，你能"看见三角形"。奇怪的地方在于：渲染器的几何里本来就有这些三角形， 可是在正常着色下你看不见它们 —— 你当时看见的是「硬棱」，而不是「三角形」。 换句话说，大脑把亮度断层解释成了折面，而不是网格。

为什么面法线会让亮度在共享边上突变？把着色写成函数：

着色 = 法线的函数 Lo(p, ωo) = f(p, n, ωo) p 在三角形内部连续变化；n 却是这个三角形的常量

对同一个三角形，交点 p 连续，法线 n 恒定 —— 所以整个面是一块"平板"。 走到共享边上，p 不变，n 突然跳到隔壁三角形的面法线。 两个相邻像素取到了两个不同的法线，于是取到了两个不同的亮度。

面法线 f = unit( (b − a) × (c − a) ) 三个顶点唯一决定，没有自由度 —— 几何的函数，不是数据

一条 rings × segments 的球，相邻两条纬线之间的法线夹角大约是 π / rings。取 rings = 6，就是 30°。 30° 的法线跳变，在漫反射下等价于亮度跳 1 − cos30° ≈ 13%；镜面反射下更狠（后面 07 节算）。 这就是你看到的那条棱。

这里容易搞混 6×10 的球，轮廓也是折线 —— 那是几何真的不够密。 但内部那片"一块一块的平"，是法线的错，几何再密也救不了（只要你还用面法线）。 两种误差独立存在。Day 15 只修第二种。

在右边舞台上把「着色」切到 法线颜色，然后拉「网格密度」从 4 到 20。 注意两件事：色块越来越小（几何在逼近），但色块之间的台阶永远是硬的（法线不连续）。

02关键洞察：顶点法线不必等于面法线

Day 14 里，Triangle 只有面法线，看起来天经地义 —— 三角形是平的，法线当然是那个平面的法线。 但 HitRecord.normal 从来没有说过它必须是面法线。它的契约只有一条：

include/hittable.hHitRecord
struct HitRecord {
    Point3 p;      // 交点位置
    Vec3   normal; // 交点处的法线（必须是单位向量！）
    double t;      // 交点对应的光线参数
    ...
};

面法线是几何的函数；顶点法线是数据。前者被三个顶点唯一决定，后者是建模时额外存下来的 一份信息 —— OBJ 文件里那些 vn 行就是它。它允许不等于任何相邻面的法线， 也允许相邻三角形共享同一个顶点法线。

把这件事画成剖面图最清楚：一段圆弧，用折线逼近。每个折线段的中垂线就是面法线， 它在折点处突变；而从圆心指向折点的射线才是顶点法线，它绕一圈是连续的。

球面是最幸运的情况：顶点法线有解析解，不需要估。

球面：法线 = 归一化的相对位置 nk = ( ak − C ) / r a_k 是第 k 个顶点，C 是球心，r 是半径。这已经是单位向量

一般模型没有这个待遇。一张任意 OBJ 网格，顶点法线只能靠「把共享该顶点的所有面法线做面积加权平均」 估出来 —— 那是 Day 16 的事。今天先用球把机制讲透，因为球能给出可验证的真值。

动手前先想清楚 顶点法线一旦和面法线不一致，set_face_normal() 里的那个朝向判断就变得可疑了。 front_face 是用方向算的（dot(d, n) < 0），如果传进去的是插值法线， 翻面逻辑就会跟着插值法线走，而不是跟着几何走。今天我们的做法是：插值完再交给 set_face_normal， 并且球面的顶点法线都是外法线，所以行为正确。但这个坑在薄壁模型上会炸（见 09 节 Q3）。

03位置怎么插值，法线就怎么插值

Day 13 我们把 Quad 上的点写成了 P = Q + α·u + β·v， 并且算出了 α = dot(w, cross(p, v))、β = dot(w, cross(u, p))。 Triangle 只是把 u、v 指向了另外两个顶点： u = b − a，v = c − a。代进去：

三角形上的点 P = a + α(b − a) + β(c − a) = (1 − α − β) · a + α · b + β · c 三个权重：w₀ = 1−α−β，w₁ = α，w₂ = β，且 w₀ + w₁ + w₂ = 1

权重和为 1 这件事不是巧合，它是"仿射组合"的定义，也是后面所有推导的地基。 正因为和为 1，这个式子换到任何坐标系下都成立 —— 它不依赖原点选在哪。 （如果权重和是 2，你算出来的就不是"点"，而是一个被平移过的位置。）

这三个权重就是重心坐标。几何上它们是面积比：

α = S(a,P,c)S(a,b,c)   (顶点 b 对面的那块) β = S(a,b,P)S(a,b,c)   (顶点 c 对面的那块) S 表示三角形面积；用叉积算，和 Day 13 的 w = n/(n·n) 是同一个式子的两种写法

于是插值法线不需要任何新工具，把 a、b、c 换成 n₀、n₁、n₂ 就行：

Day 15 的全部数学 nraw = (1 − α − β)·n0 + α·n1 + β·n2 n = nraw / ‖nraw‖ 同一组权重，作用在另一份数据上。就这两行。
include/triangle.h光滑着色
// 新增构造函数：把三个顶点法线一起存进来
Triangle(const Point3& a, const Point3& b, const Point3& c,
         const Vec3& n0, const Vec3& n1, const Vec3& n2,
         std::shared_ptr<Material> mat)
    : Quad(a, b - a, c - a, mat),     // 几何还是交给 Quad
      n0(n0), n1(n1), n2(n2), smooth(true) {}

void set_hit_normal(const Ray& r, HitRecord& rec,
                    double alpha, double beta) const override {
    if (!smooth) {                    // 平面着色：退回基类实现
        Quad::set_hit_normal(r, rec, alpha, beta);
        return;
    }
    Vec3 n = (1 - alpha - beta) * n0 + alpha * n1 + beta * n2;
    rec.set_face_normal(r, unit_vector(n));
}

为什么这样就"没有棱"了连续性论证

这是整个方法最要紧、也最容易被跳过的一步。考虑一条共享边，两个三角形 T₁、T₂ 共用顶点 b、c，它们的顶点法线都是 n₁、n₂（共享顶点 → 法线也一样）。

边上 P 落在 b、c 之间，所以 a 的权重 w₀ = 0。于是：

P = b + t(c − b) nraw = (1 − t)·n1 + t·n2 T₁ 和 T₂ 在边上的插值结果【完全一样】—— 因为这个式子只用到共享的两个顶点

这就是光滑着色的全部秘密：边上的法线只由边的两个端点决定，与两侧三角形长什么样无关。 所以两侧算出来的法线在边上逐点相等 → 亮度连续 → 没有断层 → 没有棱。

一句话记住 面法线的不连续，来自"每个三角形各自算一份"；插值法线的连续，来自"相邻三角形共享同一份顶点数据"。 共享，才是关键。这也是为什么 OBJ 里顶点要带自己的法线索引。

舞台上那个三角形的三个顶点法线故意设成不一样（和单元测试的取值一致）。 把 α、β 拖到三角形外面（α + β > 1），is_interior() 会返回 false， 命中判定失败 —— 你会发现探针变灰、读数变成"未命中"。这是 Day 14 的闭集判定还在工作。

04归一化：那一行不能省，而且原因比"看起来暗"更深

插值是线性的，法线长度不会跟着保持。这不是精度问题，是三角不等式：

为什么长度一定 ≤ 1 ‖nraw‖ = ‖ Σ wk nk ‖ ≤ Σ wk ‖nk‖ = Σ wk = 1 等号成立 ⟺ 所有 n_k 同向（那才是真平面）。只要法线之间有夹角，就一定短。

极端例子：两个互相垂直的单位法线，取中点。 n = 0.5·(1,0,0) + 0.5·(0,1,0) = (0.5, 0.5, 0)， 长度 √(0.25+0.25) = 0.7071 —— 短了 29.3%。

一般情形也很好算。两条法线夹角为 2φ，对称地取中点：

中点长度 = cos φ ‖(1−t)n0 + tn1‖² = (1−t)² + t² + 2t(1−t)cos 2φ 在 t = ½ 处取最小值：‖n‖min = cos φ φ 就是"半个夹角"，也就是这段圆弧的张角的一半。φ=45° → 0.7071，φ=11.1° → 0.9813

右边舞台把这个函数画出来了：把夹角从 4° 拉到 170°，看曲线最低点怎么掉下去。 注意 90° 那个坑（0.7071）和单元测试 B 组的 0.9813（短 1.87%）—— 它们是同一条曲线上的两个点。

所以 devlog 里那句"不归一化，光照强度就系统性偏暗"是保守说法。 对哑光是偏暗，对金属是连方向都错 —— 这在那天的金属球实验里会直接表现为反射条纹位置不对。

05球面为什么是"精确"的 —— 以及 1.2e−6° 究竟是什么

单元测试 D 组给出的数字是：光滑着色 1.207e−06°，平面着色 10.5468°。 差 7 个数量级。很多教程到这里就说"近似得很好"，但这是错的 —— 在球面上，它是恒等式，不是近似。

第一步：球面的解析法线

球面参数化 S(u,v) = C + r·d(u,v)，  d = ( sin v·cos u , cos v , sin v·sin u ) |d| ≡ 1（代入验算：sin²v·cos²u + cos²v + sin²v·sin²u = sin²v + cos²v = 1）

曲面法线是 ∂S/∂u × ∂S/∂v 的方向。但这里根本不用算：d 的长度恒为 1， 意味着 d·∂d/∂u = 0（对 |d|²=1 求导），同理对 v 也成立。 所以两个切向量都垂直于 d，而三维里垂直于一个方向的方向只有一个平面 —— 法线方向就是 d 本身。

解析法线 n(u,v) = d(u,v) = ( p − C ) / r 注意：这是"单位化的相对位置"。位置和法线在这里是同一个东西。

第二步：把插值结果算出来

把每个顶点的法线 nk = (ak − C)/r 代进插值式：

权重和为 1 的威力 nraw = Σ wk (ak − C)/r = ( Σ wk ak − C·Σwk ) / r = ( P − C ) / r Σw_k a_k 正是插值出来的交点 P；Σw_k = 1 让 C 被原封不动提出来

于是：

unit(nraw) = ( P − C ) / ‖P − C‖ = d(P 的角方向) 右边正是解析法线。所以插值法线与解析法线【逐点恒等】，误差为 0。
为什么能这么巧 因为球面的法线场 恰好是位置的线性函数（差一个常数再除以 r）， 而插值是线性的 —— 线性函数与线性插值可交换： interp(a_k/r) = interp(a_k)/r。 换任意 OBJ 模型，顶点法线是估出来的、不是位置的线性函数，这个交换律立刻失效， 那时才只有"近似光滑"。

第三步：那 1.2e−6° 是什么

是测量工具的噪声。测试用 acos(dot(a,b)) 算夹角。当两个向量几乎同向时， dot 接近 1，而 acos 在 1 附近是垂直的 —— 它的条件数会爆炸：

dot = 1 − ε  ⟹  acos(1−ε) ≈ √(2ε) ε ≈ 1e−16（double 的相对精度） ⟹  √(2e−16)·(180/π) ≈ 8e−7 ° 实测 1.2e−6° 与这个数量级一致 —— 说明真正的误差已经低于"能测出来"的地板

这句话对做数值实验的人很重要：看到 1e−6 时，先怀疑尺子，再怀疑被测对象。 如果真要验证恒等性，正确做法不是算夹角，而是直接检查向量差 ‖unit(interp) − unit(P−C)‖ 的量级。

第四步：但几何确实有误差

注意 nraw 的长度是 ‖P−C‖/r ≤ 1 —— 因为交点 P 在三角形平面里，是"凹进"球内的。设 P 相对球心的角偏移为 ψ，则

‖nraw‖ = ‖P−C‖/r = cos ψ 这就是 04 节那条曲线的三维版本，也是测试 B 组"短 1.87%"的来源：cos ψ = 0.9813 → ψ ≈ 11.1°

所以正确的结论是分层的：

对象是否改变说明
法线方向精确（恒等）球面特例：线性 + 归一化的位置
法线长度（插值原始值）变短 cos ψ被归一化修掉了，但它是"内凹"的证据
交点位置 p、距离 t完全不变几何一个字节没动，t 之差 < 1e−12
剪影完全不变轮廓由几何决定，法线救不了它

06设计难题：α、β 在 is_interior 之后就"消失"了

数学只有两行，代码却要动结构。原因很具体：在 Quad::hit() 里， (α, β) 是在函数中间算出来的局部变量，而唯一把它交给派生类的通道是 is_interior(α, β) —— 那个函数只返回 bool。等到该算法线的时候（函数末尾），派生类已经看不见 α、β 了。

alpha, beta → is_interior(alpha, beta) → rec.set_face_normal(r, normal)              ↑ 派生类能看见，但只能回答"是/否"   ↑ 派生类看不见 α、β 了

三个方案，只有第三个是对的：

方案做法问题
A 把 α、β 存进 HitRecord (α,β) 是"平面内坐标"，只对 Quad 族有意义。材质拿到它也不知道顶点法线在哪 —— 数据放错了层。
B 在 Triangle 里重写整个 hit() 要复制 40 行平面求交。以后改一处（比如加个 epsilon）就要改两处，迟早不同步。
C 再加一个虚函数钩子 ✅ 基类流程唯一，派生类只填"变化的那一步"
include/quad.h骨架 + 钩子②
bool hit(const Ray& r, double t_min, double t_max, HitRecord& rec) const override {
    ...                                  // ① 射线 × 平面求交
    ...                                  // ② 算 α、β
    if (!is_interior(alpha, beta)) return false;   // ③ 钩子①：形状
    ...
    rec.t = t;  rec.p = intersection;  rec.mat = mat;   // ④ 填记录单
    set_hit_normal(r, rec, alpha, beta);               // ⑤ 钩子②：法线
    return true;
}

// 默认实现：面法线。参数名省略 —— 签名保留，但不引入变量，
// 天然没有 -Wunused-parameter 警告
virtual void set_hit_normal(const Ray& r, HitRecord& rec,
                            double /* alpha */, double /* beta */) const {
    rec.set_face_normal(r, normal);
}

这叫 模板方法模式（Template Method）：基类把流程写死，只把中间变化的几步做成 virtual。Day 14 我们把「形状」做成钩子，今天把「法线」也做成钩子。 一个管 is_interior，一个管 set_hit_normal —— 明天加圆盘、椭圆、任意曲面，还是只写这两三个函数。

别忘了这一步 Triangle::set_hit_normal 的 签名必须和基类完全一致，包括末尾的 const。 原因见下 —— 这是今天最有教学价值的一处编译错误。

编译器报了 3 个 error，根因只有 1 个C++ 细节

构建输出第一版忘了写 const
quad.h:138: error: passing 'const Quad' as 'this' argument discards qualifiers
triangle.h:40: error: marked 'override', but does not override
triangle.h:44: error: passing 'const Triangle' as 'this' argument discards qualifiers

两层原因，叠在一起：

  1. hit() 是 const 成员函数，它向调用者承诺"我不修改 *this"。 所以在它内部只能调用 const 成员函数 —— 否则等于间接修改自己，承诺破裂。这解释了第 1、3 条。
  2. 更隐蔽的是：const 是函数签名的一部分。 void f(double) 和 void f(double) const 是两个不同的函数，可以同时存在。 所以 Triangle 那个带 const 的版本压根没有"覆盖"基类版本，它只是新增了一个同名函数。 第 2 条 error 就是在说这件事。
★ override 救了你 如果没写 override，这个错误会编译通过、正常运行： Triangle::set_hit_normal 变成一个隐藏基类同名函数的新函数，而 Quad::hit() 里那句调用 永远走基类版本 —— 插值代码一行都不会执行。 没有报错，画面只是"光滑着色好像没生效"。这种 bug 能查一下午。

07一个实验设计的教训：哑光材质看不出差别

第一版实验用 Lambertian 渲染 flat 和 smooth，结果几乎一模一样。 如果就此收工，你会得出"光滑着色没用"的结论 —— 而真相是这个材质本来就不吃法线。

为什么？把两种材质的着色对法线的敏感度写出来对比：

哑光：半球积分把法线的变化"摊平"了 Lo = ρπ ∫Ω Li(ω) cos θ dω 法线变了，积分区域跟着转 —— 但环境光大致均匀时，旋转一个近似均匀的积分几乎不改变结果
金属：反射方向 = 法线的镜像，误差翻倍 r = d − 2(d·n)n n 转过 δ  ⟹  r 转过 2δ 镜面反射对法线的角度敏感度是 2:1；而它看到的又是"清晰"的环境，任何折线都会原样印在球面上

这就解释了两件事：为什么差别在金属上剧烈，以及为什么 devlog 最后把主场景材质换成了 Metal(Color, 0.03)。0.03 的 fuzz 几乎是完美镜面 —— 故意留一点点模糊，好让"镜面里的折线"更明显。

材质flat vs smooth 视觉差异原因
Lambertian几乎看不出半球积分的平均效应，一阶不敏感
Metal（镜面）严重反射方向完全由法线决定，且角度误差 ×2
可以迁移的教训 验证一个视觉效果之前，先问：这个效果作用在哪个量的哪一阶上？ 你要验证法线，就必须选一个"直接看法线"的材质。 用哑光验证光滑着色，等价于用降噪耳机测试高音单元 —— 不是没差别，是通路被堵住了。

左边舞台上有一个「差异图」模式：它把 flat 和 smooth 各渲一遍，逐像素取绝对值差，再放大显示。 你会看到球内部整片亮起（法线确实变了），而轮廓线上一片漆黑（几何确实没变）。 这是"只改法线不改几何"最直接的证据 —— 比任何文字都硬。

差异图的数学 Δ(x,y) = ‖ Cflat(x,y) − Csmooth(x,y) ‖ 若某个像素的 Δ = 0，说明两种着色在这一点给出了完全相同的颜色 —— 轮廓像素正是如此
反直觉点，值得单独讲 "看起来更圆" ≠ "几何更圆"。前者是着色问题，后者是建模问题。 光滑着色改变的是"每个点怎么反射光"，不改变"光能打到哪些点"。 想让剪影真的变圆，唯一的办法是加密网格 —— 或者在光栅化里做抗锯齿/在光追里让像素对轮廓积分， 那是另一条路（Day 17+ 的 AA）。

自检题先自己想，再展开

为什么插值完必须归一化？不归一化会怎样？
线性插值会缩短长度：两个互相垂直的单位法线在中点插值得 (0.5, 0.5, 0)，长度只有 0.707。 HitRecord.normal 的契约是单位向量，Lambertian 的 normal + random_unit_vector() 和 Metal 的 reflect 都依赖这一点。不归一化：哑光 系统性偏暗（分布被压窄、有偏）， 金属反射方向本身就错（翻转量只剩 k²，k = 0.9813 时是 96.3%）。
光滑着色会改变物体的剪影吗？为什么？
不会。它只改 rec.normal，不改 rec.p、rec.t、也不改三角形顶点。 剪影 = "光线能打到哪些点"，完全由几何决定。实测两种着色的 t 误差 < 1e−12。 舞台上打开差异图，轮廓那一圈会一直是黑的。
如果相邻两个顶点的法线夹角超过 90°，插值会发生什么？
中间会出现 n ≈ 0 的点（两条接近反向的法线插值，长度趋近 0）， unit_vector 除以接近 0 的长度 → 数值爆炸成 NaN / Inf。 真实模型里确实会出现：薄壁物体（一张纸、一片叶子）两面法线恰好相反。 工业界的处理：按面拆分顶点（不共享顶点），或者用切线空间 / 双面材质（two-sided）。 这也是为什么很多引擎要求法线贴图的法线必须和几何外法线同向。
对任意 OBJ 网格（不是球），顶点法线该怎么算？
把共享该顶点的所有面法线做面积加权平均（面积大的面贡献多），再归一化： n_v = unit( Σ_f A_f · f_f )。 面积加权是因为大三角形对"局部形状"的代表性更强；等权平均会让细碎三角形过度影响结果。 球面有解析解是特例 —— 一般模型只能这样估，所以只有"近似光滑"。
为什么把 set_hit_normal 做成虚函数，而不是在 Triangle 里重写 hit()？
重写 hit() 要复制 40 行平面求交代码，以后改一处就要改两处（迟早不同步）。 虚函数钩子让 Quad::hit() 保持唯一一份，派生类只填变化的那一步 —— 模板方法模式。 这也是 Day 14「Triangle 只写一个函数」的延续：继承的成本是"理解基类流程"，收益是"不必复制"。
（加餐）为什么球面上"精确"，而任意模型只是"近似"？
因为球面的法线场是位置的线性函数：n = (p−C)/r。 线性函数与线性插值可交换，所以插值法线正比于插值位置减球心，归一化后逐点等于解析法线。 任意模型上顶点法线是估出来的，不是位置的线性函数，交换律不成立 —— 只能保证"看起来连续"，不能保证"等于真法线"。
